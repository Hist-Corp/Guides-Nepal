# Deployment Guide — Guides Nepal

> This is the single source of truth for deploying Guides Nepal. It replaces the older
> one-off guides (`COMPLETE_DEPLOYMENT_GUIDE.md`, `DEPLOYMENT_GUIDE.md`,
> `DEPLOYMENT_GUIDE_STEP_BY_STEP.md`, `QUICK_START_DEPLOYMENT.md`, `VERCEL_*`, `RENDER_*`,
> `DEPLOYMENT_PROGRESS.md`, `FIX_PERMISSION_ERROR.md`), which now point here.

## Architecture of the deployment

| Component | Stack | Platform | Notes |
|-----------|-------|----------|-------|
| Frontend (public site) | Vite + React 18 | Vercel | Root directory `frontend`, build 
pm run build`, output `dist` |
| Dashboard (RBAC app) | Vite + React 18 | Vercel (separate project) | Root directory `dashboard`, build 
pm run build`, output `dist` |
| Backend API | FastAPI + SQLAlchemy | Render (Docker) | Blueprint in `render.yaml`, Dockerfile at `backend/Dockerfile` |
| Database | PostgreSQL | Supabase | Connected via `DATABASE_URL` on the backend |

Current production URLs (update as needed):

- Frontend: `https://guides-nepal-nine.vercel.app`
- Dashboard: `https://guides-nepal-bi2y.vercel.app`
- Backend: `https://guides-nepal.onrender.com` (health check: `GET /health`)

## 1. Prerequisites

1. A GitHub repository with this code pushed to `main`.
2. Accounts on [Vercel](https://vercel.com), [Render](https://render.com), and [Supabase](https://supabase.com).
3. A Supabase project with its PostgreSQL connection string (`DATABASE_URL`) and
   `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` values (used for password-reset emails).

---

## 2. Backend on Render (Blueprint)

The repo root contains `render.yaml`:

- Service type: web (Docker), Dockerfile `backend/Dockerfile`, health check `/health`.
- `SECRET_KEY` is auto-generated by Render (`generateValue: true`).
- `DATABASE_URL`, `OPENAI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` are
  `sync: false` — set them as secrets in the Render dashboard (Service → Environment).

Steps:

1. Render dashboard → **New +** → **Blueprint** → connect the GitHub repo.
2. Render reads `render.yaml`. Fill in the `sync: false` secrets:
   - `DATABASE_URL` = `postgresql://postgres:<SUPABASE_DB_PASSWORD>@db.<PROJECT_REF>.supabase.co:5432/postgres`
     (URL-encode special characters, e.g. `@` → `%40`).
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` from the Supabase project.
   - `OPENAI_API_KEY` (optional; AI falls back to Ollama/local behavior when unset).
3. Deploy and watch logs. On success, `GET /health` returns `{"status":"ok","environment":"production"}`.

Backend startup behavior (see `backend/app/main.py`):

- Runs `Base.metadata.create_all(...)` on startup, so tables exist even before Alembic migrations run.
- Mounts `/uploads` for static files; if the filesystem is read-only the mount is skipped with a warning (not fatal).
- In production (`ENV=production`): API docs (`/api/v1/docs`) are disabled, HTTPS is enforced,
  non-HTTPS CORS origins are rejected at startup, and the app refuses to boot if `SECRET_KEY`
  still equals the dev default.

## 3. Frontend on Vercel

1. Vercel → **Add New Project** → import the GitHub repo.
2. **Root Directory**: `frontend`, Framework preset: Vite, Build: 
pm run build`, Output: `dist`.
3. Environment variables (from `frontend/.env.example`):
   | Name | Value |
   |------|-------|
   | `VITE_API_URL` | `https://guides-nepal.onrender.com` |
   | `VITE_SUPABASE_URL` | `https://<PROJECT_REF>.supabase.co` (if used) |
   | `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase anon key (if used) |
   | `FRONTEND_OAUTH_REDIRECT` | `https://<frontend-url>/auth/callback` |
   | `VITE_GOOGLE_OAUTH_URL` | `https://guides-nepal.onrender.com/api/v1/auth/oauth/google/start` |
   | `VITE_FACEBOOK_OAUTH_URL` | `https://guides-nepal.onrender.com/api/v1/auth/oauth/facebook/start` |
4. Deploy and note the URL.

## 4. Dashboard on Vercel

1. Repeat the above with **Root Directory**: `dashboard`.
2. Environment variables (from `dashboard/.env.example`):
   - `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`
   - `VITE_API_BASE_URL` = `https://guides-nepal.onrender.com/api/v1`
3. Deploy and note the URL.

## 5. Update CORS on the backend

Set `BACKEND_CORS_ORIGINS` in the Render dashboard to a comma-separated list of the
production origins (must be HTTPS — the backend validates this at startup):

```
https://guides-nepal-nine.vercel.app,https://guides-nepal-bi2y.vercel.app
```

Saving redeploys the service automatically.

## 6. Docker (local/self-hosted)

`docker-compose.yml` at the repo root starts everything:

```bash
docker compose up --build
```

| Service | URL |
|---------|-----|
| Frontend | http://localhost:5175 |
| Dashboard | http://localhost:5176 |
| Backend | http://localhost:8000 |
| PostgreSQL | localhost:5432 (`postgres:postgres`, db `guides_nepal`) |

Supabase-related variables are passed through from your shell/environment
(`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_URL`,
`SUPABASE_SERVICE_ROLE_KEY`, `RESET_PASSWORD_REDIRECT_URL`).

---

## 7. Post-deployment checklist

- [ ] `GET https://<backend>/health` returns `{"status":"ok","environment":"production"}`
- [ ] API docs hidden (`/api/v1/docs` → 404 in production)
- [ ] `SECRET_KEY` not the dev default (backend refuses to boot otherwise)
- [ ] `BACKEND_CORS_ORIGINS` contains only production HTTPS origins
- [ ] Register/login works from the deployed frontend
- [ ] Password-reset emails land with `RESET_PASSWORD_REDIRECT_URL` set to the deployed frontend
- [ ] All default/seed credentials changed (see `SECURITY.md`)

See also [SECURITY.md](./SECURITY.md) for the full pre-deployment security checklist.
