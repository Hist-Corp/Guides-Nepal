## Implemented security (backend)

Source: `backend/app/core/config.py`, `backend/app/core/security.py`, `backend/app/core/middleware.py`.

### Configuration & environment
- `ENV` flag (`development` / `production`); `DEBUG` derived from it.
- **SECRET_KEY validation**: the app raises at startup in production if `SECRET_KEY` is still the dev placeholder.
- **HTTPS-only origins in production**: any non-`localhost` `http://` CORS origin raises at startup.
- Password policy: min 8 chars, uppercase, numbers, and special characters required.
- Rate limiting settings: 100 requests / 60 s window (`RATE_LIMIT_ENABLED`, `RATE_LIMIT_REQUESTS`, `RATE_LIMIT_PERIOD`).
- Dev-only seeding guarded by `DEV_ALLOW_SEED` (ignored when `ENV=production`).

### Middleware stack (order matters)
1. `SecurityHeadersMiddleware` — `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `X-XSS-Protection`, HSTS (non-dev), CSP.
2. `RequestLoggingMiddleware` — request logging for auditing.
3. `InputValidationMiddleware` — blocks SQL-injection patterns, XSS patterns, and path traversal.
4. `HTTPSEnforcementMiddleware` — enforces HTTPS in production.

### Authentication
- JWT (HS256): access tokens 30 min, refresh tokens 7 days; token-type validation.
- Passwords hashed with bcrypt.
- OAuth flows for Google and Facebook (`/api/v1/auth/oauth/*`).
- Password reset via Supabase email verification (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RESET_PASSWORD_REDIRECT_URL`).
- CORS restricted to `BACKEND_CORS_ORIGINS` with explicit allow-listed methods/headers.
- Global exception handler returns generic `{"detail": "Internal server error"}` in production; API docs disabled unless `ENV=development`.

### RBAC (roles)
Canonical roles in `backend/app/core/roles.py`:

```
super-admin > admin > content-writer > regional-head > customer-support > host > guide > traveler
```

- Super-admin implicitly passes every role guard via `has_access()`.
- Dashboard roles: `super-admin`, `admin`, `content-writer`, `regional-head`, `customer-support`, `host`, `guide`.

## Frontend security
- Environment validation (HTTPS Supabase URL) and input sanitization utilities.
- Login-attempt throttling; tokens kept out of long-lived storage.
- CSP and other headers are set by the backend; Vercel serves over HTTPS.

## Pre-deployment security checklist

- [ ] `SECRET_KEY` generated fresh (`openssl rand -hex 32`) and set in Render — never committed.
- [ ] `DATABASE_URL` uses a strong Supabase password (URL-encoded special chars) with SSL.
- [ ] `ENV=production` on Render.
- [ ] `BACKEND_CORS_ORIGINS` lists only production HTTPS URLs.
- [ ] `/api/v1/docs` returns 404 in production.
- [ ] Security headers present: `curl -i https://<backend>/health`.
- [ ] All development seed credentials changed (e.g. `admin@guides-nepal.com / Admin@12345` — dev only).
- [ ] `DEV_ALLOW_SEED` not set in production.
- [ ] Run `bandit -r backend/app` before release.

## Environment variable reference

### Backend (Render dashboard — `render.yaml` keeps secrets as `sync: false`)
| Variable | Required | Notes |
|----------|----------|-------|
| `DATABASE_URL` | ✅ | Supabase/PostgreSQL connection string |
| `SECRET_KEY` | ✅ | Auto-generated by Render blueprint or set manually |
| `ENV` | ✅ | `production` |
| `BACKEND_CORS_ORIGINS` | ✅ | Comma-separated HTTPS origins |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | for reset emails | Backend password-reset verification |
| `RESET_PASSWORD_REDIRECT_URL` | for reset emails | Must be allow-listed in Supabase "Redirect URLs" |
| `OPENAI_API_KEY` | optional | Enables OpenAI provider for AI chat |
| `AI_PROVIDER` / `AI_MODEL` / `OLLAMA_URL` / `OLLAMA_MODEL` | optional | AI chat config (`auto` by default) |
| `GOOGLE_*` / `FACEBOOK_*` OAuth vars | optional | Social login |
| `LOG_LEVEL` | optional | Default `INFO` in production |

### Frontend (Vercel)
`VITE_API_URL`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`,
`FRONTEND_OAUTH_REDIRECT`, `VITE_GOOGLE_OAUTH_URL`, `VITE_FACEBOOK_OAUTH_URL`,
`VITE_ENABLE_AI` (see `frontend/.env.example`).

### Dashboard (Vercel)
`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_API_BASE_URL`,
`VITE_DEV_FAKE_LOGIN` (dev only — never in production; see `dashboard/.env.example`).
